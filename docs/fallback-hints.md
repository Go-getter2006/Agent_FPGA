# 规则提示模板（阶段 3）

大模型不可用时、以及对照组使用的提示（docs/llm-deepseek.md 第 8 节）。模板在 `backend/app/services/fallback_hints.py`，本文件由它生成，供审阅。

- `{…}` 里的变量全部从裁判诊断取值：STEP、信号名、期望值 / 实际值、驱动行号、锁存器信号、工具原话等
- 模板里不含任何代码，只有中文说明、信号名、行号和工具原话；有测试检查每条模板都不像代码
- 一次诊断有多个标签时，按下表从上到下取第一个；都没有时看预测是否有没对上的格子
- `sim_mismatch` 的 2 级会按象限加一句引导：设计偏差 →“问题出在设计思路上，回到题目说明”；概念未通 →“先弄清代码真正做了什么”

## 编译没通过（`compile_error`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | 第 {error_line} 行附近没有通过编译，工具的原话是：“{error_message}”。先看这一行和它的上一行。 | 这里是不是少了分号或括号，或者把 reg 和 wire 用混了？ |
| 2 级·概念 | 编译器按语法一句一句地读代码，报错的行号常常落在真正出错位置的下一行。在 always 块里被赋值的信号要声明成 reg，用 assign 驱动的信号要声明成 wire。 | 报错涉及的信号是在哪里被赋值的？它的声明和赋值方式对得上吗？ |
| 3 级·类比 | 这就像写中文时漏了句号：读的人会把两句话连在一起读，到下一句才发现读不通。 | 从报错的那一行往上找一句，哪一句像是“没写完”？ |

## 写了不能综合成电路的语句（`non_synthesizable`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | 仿真能跑，但 Yosys 综合时报错：“{synth_error}”。 | 这段代码里，有没有哪种写法只有在“一步一步执行的程序”里才说得通？ |
| 2 级·概念 | 综合是把代码变成一块固定的电路，电路有多大在综合时就要确定，所以循环的次数必须是常数；像“一直找到满足条件为止”这样的循环，只能在仿真里执行，变不成电路。 | 你的循环要转几圈，是写死的，还是取决于输入？ |
| 3 级·类比 | 就像盖房子前必须先定下有几层楼，不能边住边决定要不要再加一层。 | 能不能把“找到为止”的写法，改成把每一种情况都直接列出来？ |

## 结果依赖 always 块的先后顺序（`race_order_sensitive`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | 顺序打乱实验显示：交换 always 块的先后之后，第 {shuffle_step} 步的 {shuffle_signal} 从 {shuffle_base} 变成了 {shuffle_variant}。 | 哪两个 always 块在同一个时钟沿读写了同一个信号？ |
| 2 级·概念 | 交换 always 块的先后，结果就变了，而真实电路里的各个部分是同时工作的，没有先后。 | 哪两个块在同一个时钟沿读写了同一个信号？它们读到的是旧值还是新值？ |
| 3 级·类比 | 想象两个人交换手里的卡片：如果一个人先放下卡片、另一个人再去拿，结果就看谁动作快；真实的触发器像是两人先看清对方手里的卡片，等口令一响再同时交换。 | 哪一种赋值方式对应“先看清、再一起换”？ |

## 组合逻辑没写全，生成了锁存器（`latch_inferred`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | Yosys 说 {latch_signals} 被综合成了锁存器。 | 在组合 always 块里，有没有哪种情况没给它赋值？ |
| 2 级·概念 | 组合逻辑的输出必须在每一种输入下都有确定的值；漏掉的分支会让电路“记住”旧值，这就是锁存器。 | 你的 if 或 case 覆盖了所有情况吗？ |
| 3 级·类比 | 就像一张查分表，只写了 60 分以上对应的等级，没写 60 分以下；查到没写的那一行，只好沿用上一个人的结果。 | 你的代码里，哪一种情况相当于“表里没写”？ |

## 同一个信号被多处赋值（`multi_driven`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | Yosys 发现同一个信号有多个驱动源：{multi_signals}。 | 这个信号在几个地方被赋值了？分别在哪几行？ |
| 2 级·概念 | 电路里一根导线只能由一个地方驱动。两个 always 块（或两条 assign）同时驱动它，就像两个人同时往一根线上送不同的电压。 | 能不能把对这个信号的所有赋值放进同一个 always 块里？ |
| 3 级·类比 | 一块黑板同一时间只能由一个人负责写；两个人各写各的，最后黑板上是什么就说不清了。 | 这个信号真正该“听”哪一处赋值？ |

## 时序逻辑里用了 =（阻塞赋值）（`blocking_in_seq`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | Verilator 提示第 {lint_lines} 行在时序 always 块里用了 =（阻塞赋值）。 | 这几行执行完之后，后面的语句读到的是旧值还是新值？ |
| 2 级·概念 | 时序 always 块里用 = 时，后面的语句会马上读到新值；真实的触发器是在同一个时钟沿同时采样的。 | 你觉得这里该用哪种赋值？ |
| 3 级·类比 | 排队传话时，如果每个人一听到就立刻改口，最后一个人听到的已经是被改过好几次的话；触发器像是大家先记下自己听到的，等口令响起再一起改。 | 你的代码里，谁“听”到的已经是别人刚改过的值？ |

## 组合逻辑里用了 <=（`nonblocking_in_comb`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | Verilator 提示第 {lint_lines} 行在组合 always 块里用了 <=（非阻塞赋值）。 | 组合逻辑的输出应该在什么时候跟着输入变化？ |
| 2 级·概念 | 组合逻辑没有时钟，输出应该随输入立即变化；块里算出的中间结果要马上能被后面的语句用到，所以组合块里用 =。 | 如果后一条语句要用前一条刚算出的结果，<= 能做到吗？ |
| 3 级·类比 | 算账时先算小计、再算总计；如果小计要等到“明天”才更新，今天的总计就会用错数。 | 你的组合块里，哪个中间结果被“推迟”了？ |

## 位宽对不上（`width_mismatch`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | Verilator 提示第 {lint_lines} 行位宽对不上：{lint_message} | 这一行左右两边各有几位？多出来或缺少的那几位去哪了？ |
| 2 级·概念 | Verilog 先按表达式里最宽的操作数决定用几位来算，赋值时多出的高位会被截掉、不够的补 0；进位和状态编码最容易在这里丢。 | 这个信号需要几位，才能装下它所有可能的值？ |
| 3 级·类比 | 就像用两位数的计数器给 100 个人编号，编到 99 之后再加 1，就回到了 00。 | 你的信号会不会遇到“装不下”的那一刻？ |

## 仿真和期望对不上（`sim_mismatch`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | 先看第 {step} 步的 {signal}：期望 {expected}，实际 {actual}。这一步之前，{signal} 由第 {lines} 行决定。 | 它们在{moment}做了什么？ |
| 2 级·概念 | {quadrant_lead}对照期望波形，看你的电路是从哪一步开始“走偏”的：是更新的时机不对（早了或晚了一拍），还是更新出来的值不对？ | 第 {step} 步的输入是 {inputs}，按题目说明，这时 {signal} 为什么应该是 {expected}？ |
| 3 级·类比 | 调试就像查账：从第一笔对不上的账往前翻，找到最后一笔还对得上的，问题就在这两笔之间。 | 第 {prev_step} 步还对得上吗？从第 {prev_step} 步到第 {step} 步，你的代码做了什么？ |

## 仿真对了，但电路描述有隐患（`fragile_pass`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | 仿真结果和期望一致，但工具还发现了隐患：{risk}。 | 这个隐患在这次仿真里为什么没有暴露出来？ |
| 2 级·概念 | 仿真只检查了 testbench 给出的这些输入；综合出来的真实电路要在所有输入、所有时刻都正确。 | 如果换一组输入，或者把电路放到真实芯片上，这个隐患会造成什么后果？ |
| 3 级·类比 | 就像一座桥晴天走得过去，不代表下雨天也安全。 | 要让它在“下雨天”也安全，代码要怎样写？ |

## 代码对了，但预测没对上（不是裁判标签）（`pred_miss`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | 代码已经对了，但你的预测有 {miss_count} 格没对上。先看第 {pstep} 步的 {psignal}：你预测 {pvalue}，实际是 {pactual}。 | 不改代码，你能说清楚为什么实际是 {pactual} 吗？ |
| 2 级·概念 | 预测没对上，常常是没想清楚信号在什么时刻更新：时序逻辑在时钟沿之后才变，组合逻辑随输入立刻变。 | {psignal} 是时序逻辑还是组合逻辑？在第 {pstep} 步之前，它经历了什么？ |
| 3 级·类比 | 就像看天气：知道今天下雨不难，难的是说清楚为什么会下雨。 | 如果把第 {pstep} 步的输入换一下，{psignal} 会变成什么？ |

## 代码和预测都对（进阶追问）（`pass`）

| 等级 | 说明 | 追问 |
|---|---|---|
| 1 级·定位 | 代码和预测都对了。 | 你能说出这个设计里哪些信号是触发器、为什么吗？ |
| 2 级·概念 | 进阶一点：功能不变，能不能用更少的触发器实现？或者换一种写法，结果还一样吗？ | 如果去掉其中一个寄存器，哪一步的波形会先变？ |
| 3 级·类比 | 真正的掌握，是能在别人的代码里一眼看出同样的问题。 | 如果同学把这里的 <= 改成 =，你能预测哪一步会先对不上吗？ |
